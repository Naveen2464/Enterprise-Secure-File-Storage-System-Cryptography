# Secure File Storage System
## Hybrid Cryptography & Secure File Handling

A from-scratch educational Python project demonstrating hybrid file encryption.

### Cryptographic design

- **AES-256-GCM** encrypts file contents and authenticates ciphertext.
- A fresh random 256-bit AES session key is generated for every file.
- **RSA-OAEP with SHA-256** wraps the AES session key for the recipient.
- **SHA-256** creates a digest of the original file.
- **RSA-PSS with SHA-256** signs the package using the sender's private key.
- The signature is verified before decryption. AES-GCM authentication and the SHA-256 digest are then checked.

> Educational/research software, not production cryptographic storage. Use synthetic or non-sensitive files. Private keys generated by this demo are unencrypted PEM files; protect them carefully. For real applications, use established audited products and a reviewed key-management design.


## Demonstration workflow

This project uses two identities: a **sender** and a **recipient**.

1. Open the **Key generation** tab and generate a key pair for the recipient. Download both PEM files. The recipient keeps the private key secret and shares the public key with the sender.
2. Generate a second key pair for the sender. The sender keeps the private key secret and shares the public key with the recipient.
3. In **Encrypt a file**, upload the recipient public key, sender private key, and a sample file. Download the `.sfs` encrypted package.
4. In **Verify & decrypt**, upload the `.sfs` package, recipient private key, and sender public key.
5. Confirm that the signature verifies and download the recovered original file.
6. For a tamper test, make a copy of the `.sfs` file and edit one character in its JSON `ciphertext` value. Verification should fail. Do not edit your only copy.

## Important notes

- AES-GCM is authenticated encryption; it detects ciphertext or associated-data tampering.
- RSA-OAEP protects the random AES session key; RSA does not encrypt the whole file.
- RSA-PSS authenticates the package as signed by the holder of the sender private key. It does not prove a real-world identity unless public keys are authenticated separately.
- The SHA-256 digest is an additional consistency check; the signature covers the digest and encrypted package metadata.
- This simple demo reads the full file into memory. It is intended for small classroom test files, not large-scale storage.
- The private-key PEM files are not password-encrypted. Never upload or share them.
